## 2. 核心用户故事清单

### US-001: 公共接口变更下的跨模态文档陈旧召回
- **作为** 一名维护大型复杂系统的架构师或开发者，
- **当我** 针对代码库中的公共核心数据结构进行重构（例如将 `UserContext.user_id` 重命名为 `UserContext.subject_id`）时，
- **我希望** 系统能够自动从历史工具调用轨迹、静态关系与语义证据中，精准召回未直接 `import` 该代码但实质依赖其语义的设计文档（如 `docs/auth_design.md`）和 API 契约文档（如 `docs/api_contract.md`），
- **以便于** 避免文档因代码变更而失修陈旧，且无需人工在大规模仓库中逐一排查。

### US-002: 局部变量重构的负对照拦截（防过度更新）
- **作为** 一名追求稳定性的工程负责人，
- **当我** 仅在模块内部对局部私有变量进行重构（不改变公共接口与行为）时，
- **我希望** 系统即使感知到该模块与上游文档存在历史相关性，也能够通过独立的陈旧验证器（Staleness Verifier）准确判定为 `VALID` 或 `NOT_APPLICABLE`，
- **以便于** 绝对不产生任何虚假补丁提案（0 误报），防止相关性滥用为修改义务。

### US-003: 最小可回滚补丁提案与目标哈希锚定
- **作为** 一名代码安全与治理评审人员，
- **当我** 审查系统识别出的陈旧陈述时，
- **我希望** 系统仅在隔离环境中生成绑定当前文件内容哈希（`expected_target_hash`）的最小 Unified Diff 补丁提案，且状态保持在 `PATCH_PROPOSED`，
- **以便于** 绝不在未获人工明确授权前私自写回工作区；若目标文件在验证后发生外生修改（哈希漂移），系统必须立即报错并终止。

### US-004: 自强化反馈回路抑制
- **作为** 一名机器学习与图算法研究员，
- **当** Agent 在接收系统推荐后访问了某份制品但未发现实质陈旧时，
- **我希望** 系统将该推荐访问与人类/自发访问（Organic）严格隔离，赋予极低权重（0.05 vs 1.0），
- **以便于** 阻止系统推荐结果在下一轮构图中自我强化，避免虚假关联形成恶性马太效应。

### US-005: 批量格式化任务超边收敛
- **作为** 系统运维与分析引擎，
- **当** 开发者或工具对数百个文件执行全局批量格式化（Bulk Format）时，
- **我希望** 系统自动识别为任务超边（`task_hyperedge`）并对关联权重执行对数反比归一化，
- **以便于** 阻止两两全连接团（Clique）导致图边数量爆炸，保护图引擎的计算与存储稳定性。
