# Q-005 数据边界

用户已接受本文件的 P0 默认数据边界。P0 整体已于 `P0-20260829-001` 批准，本文件当前为 `status: approved`；数据边界变化仍须走 G-011。

## P0 封闭数据枚举

每个被 Run 或 Evidence 引用的数据文件必须登记一个且只能登记一个 `data_class`：

| `data_class` | P0 含义 | 内容位置 | 允许范围 |
|---|---|---|---|
| `fixture` | 项目内置、确定性测试输入 | 库内受控 fixture 目录 | 用于工程闭环和回归测试；内容 hash 必须进入 RunManifest |
| `synthetic` | 人工或程序生成的非真实个体数据 | 库内受控 fixture 目录或 TaskSlice workspace | 用于工程、流程和方法演示；不得生成临床效果 Claim |
| `deidentified-sample` | 公开教学/文献虚构案例，或用户本人显著改写的样例 | 仅在登记和轻量人工确认后进入受控目录 | 默认按 potentially identifying 处理；必须记录来源、改写/脱敏方式和检查人 |
| `external-ref` | 外部数据的引用元数据，不是数据载荷 | 数据原件留在库外受控位置；库内只保留 manifest、版本、许可证、位置指针和 SHA-256 | 可用于 provenance 引用；Agent 不得自动获取或下载内容 |

除上述四类外，`unknown`、空值、临时自定义值和未登记文件均不允许进入 Run 或 Evidence 引用链。

## 强制登记字段

每个可引用数据文件或 external manifest 至少必须能解析：

- `data_class`；
- `source_id`；
- `origin`；
- `created_at` 或 `captured_at`；
- `content_hash`；
- `location` 或受控外部位置指针；
- `license_or_permission`；
- `transformation`；无变换也必须明确写明 `none`。

`deidentified-sample` 还必须登记：

- 允许进入的来源类型：公开教学/文献虚构案例，或用户本人显著改写的样例；
- 具体改写或脱敏方式；
- 检查人和检查日期；
- 未发现可识别风险的检查说明。

“删除姓名”不视为充分脱敏。日期、罕见病描述、原始编号、组合特征和上下文都必须纳入检查；在登记完成前，一律按 potentially identifying 处理。

## 可执行规则

1. 未登记 `data_class` 或来源 provenance 的数据文件，不能被任何 Run、EvidenceCard、EvidenceSnapshot 或 Claim 引用；Harness 必须 fail closed。
2. `data_class` 不在封闭枚举内，或 manifest 的 hash、版本、位置指针不匹配时，Harness 必须拒绝引用。
3. `fixture` 内容的精确 hash 必须进入对应 `RunManifest`；内容发生变化时创建新版本，不覆盖原文件。
4. `fixture` 的实质性内容变化视同测试合同变化，必须经过人工 Gate；不得借“修复测试数据”绕过 G-011。
5. Text Agent、Pi worker 和 P0 Harness 均不得主动发起网络下载或自动获取外部数据集。
6. 用户人工下载的外部原件必须留在库外受控位置；库内只登记 `external-ref` manifest，不复制真实原件或敏感原文。
7. 新增一个 `deidentified-sample` 或 `external-ref` 数据登记，必须经过一次轻量人工确认；该确认使用 Q-004 的数据/默认 Gate 语义，不新增 Gate ID。
8. 任何未被本文件、Q-004 Gate 清单或明确的非 Gate 清单覆盖的输入动作，默认进入 Gate 并 fail closed。

## Claim 表述边界

- `fixture`、`synthetic` 或 `deidentified-sample` 的工程结果，可以支持有限的工程、流程或方法表述，但必须保留 `data_class`、scope 和 limitations。
- 任何数据类别产生临床有效性或临床效果 Claim，均属于 INV-013 的绝对 deny，不能通过人工 Gate 解锁。
- public dataset / `external-ref` 结果升级为非临床科学或方法表述时，适用 G-008 的人工 Gate；升级为临床效果表述时直接 deny。

## 与 Run 和 Evidence 的绑定

```text
data registration
  → data_class + provenance + hash check
  → approved ExperimentSpec / TaskSlice
  → RunManifest records exact input refs and hashes
  → EvidenceCard / EvidenceSnapshot preserves data_class
  → Claim Gate checks scope and claim class
```

数据登记本身不改变科学结论；它只是让 Harness 能够判断某个 Run 或 Evidence 是否越过数据边界。

## P0 不允许

- 真实患者文本或未脱敏医疗数据（P0–P5 均禁止接入；任何解除或例外都必须先走 G-011）；
- Agent 自动下载、爬取或同步外部数据集；
- 将 external-ref 当作已读取、已验证的原始数据；
- 将 fixture/synthetic/public dataset 结果表述为临床有效性；
- 用人工批准替代 data_class、provenance、版本或 hash 检查。

详细 Gate 关系见 [[05_Gate清单与批准边界]]；对应可执行不变量见 `02_架构与合同/04_可执行不变量.md` 的 INV-016。
